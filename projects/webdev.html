Assignment Portal

Intro to Web Development

CSCE 242: Spring 2025

Overview

In this Web Applications course, we developed an Assignments Portal to house all of our class assignments, activities, and final projects. The portal evolved alongside our understanding of front-end and back-end web development, starting from basic HTML and CSS and growing into a full-stack environment. Alongside classwork, we were tasked with creating an individual project. I chose to design and build an online jewelry store called Gold Pebbles, which progressed from a static HTML/CSS prototype into a dynamic React-based web app with a fully functional Node.js backend hosted on Render. This hands-on project provided experience across the entire development stack from UI/UX design to server-side data handling.

Background and Purpose

The purpose of this project was to solidify our understanding of web application architecture by building progressively complex web tools throughout the semester. It began with prototyping in Mockitt, receiving feedback from peers, TAs, and the instructor, and then implementing the feedback in code. As we learned more technologies, such as JavaScript, DOM manipulation, React, Node.js, and server integration. We applied those skills in both our portal and our final individual project.

The goal was to equip us with the ability to design, develop, and deploy fully functional web applications with both client-side and server-side components. By the end of the course, we were expected to have a deeper understanding of the web dev process from ideation to deployment, including user interaction, server communication, data handling, and real-world deployment practices.

Development Challenges

Styling and Layout Learning Curve

One of the first challenges was understanding how to style elements effectively using CSS. Figuring out things like relative vs. absolute positioning, the box model, and how flexbox or grid affect layouts took some trial and error. Over time, my styling improved as I began documenting patterns that worked, creating personal notes and mini-guides for layouts, parallax effects, and other visual techniques. These references became invaluable in later stages of development.

Client-Side vs. Server-Side Switching

As we moved into full-stack development, toggling between the client side and server side became mentally demanding. It was easy to lose track of which file needed editing or where certain functionality belonged. I eventually discovered I could open multiple VS Code workspaces simultaneously, which made switching between environments much faster and more organized. I also began using keyboard shortcuts and workspace splitting to increase productivity.

API Communication and Data Fetching

Another hurdle was understanding how to fetch data from the backend and display it on the frontend. At first, I struggled with routing, formatting fetch calls, and parsing JSON data correctly. The challenge stemmed from wrapping my head around asynchronous logic and making sure the backend was properly set up to respond to the requests. Eventually, I learned to structure my API routes more clearly and use console.log() strategically to debug and ensure the data flow was smooth. This experience taught me the importance of consistent testing and validating every part of the request-response cycle.

Full-Stack Integration

The most ambitious part of the project was rebuilding the jewelry store (Gold Pebbles) from a static design to a React app with a working Node.js backend. Hosting the backend on Render required careful setup and awareness of deployment pitfalls. This full-stack integration taught me how to work with client-server architecture, handle asynchronous requests, and debug issues related to live environments versus local development.

Conclusion

This course pushed me to explore and understand the full spectrum of web development, from basic HTML and CSS to deploying a full-stack application. Creating Gold Pebbles challenged me to think critically, stay organized, and adapt quickly to new technologies. Along the way, I developed strategies to improve workflow, documented my learning for future reference, and overcame real-world development obstacles like styling bugs, backend communication errors, and deployment headaches.

The project remains an ongoing learning experience, and I now feel more confident in my ability to develop and deploy scalable web applications from scratch. I look forward to refining this project further and applying these skills to future development work.
